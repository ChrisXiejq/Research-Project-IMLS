## 1. 与 `Experiment Flow.png` 的对应（闭环 + 三方法）

| 流程图模块 | 本仓库实现（intersection） |
|------------|-----------------------------|
| **Scenario Config (JSON)** | `core/scripts/carla/scenarios/scenario_0*.json`；由 `run_all_scenarios.py` 读入并构造 `VehicleParams` |
| **CARLA Simulation World** | `run_intersection_scenario.py`：`RunIntersectionScenario._setup_carla_world`、`_setup_vehicles` |
| **State / 观测** | 各 policy 的 `run_step`：从 `carla.Vehicle` 读位姿、速度等（即图中的 \(x_t\)、他车状态） |
| **Multimodal Predictor (MultiPath)** | `_setup_predictions` 加载 `DeployMultiPath`；每帧 `_make_predictions` 中 `gmm_pred_tv.get_top_k_GMM` → `tvs_mode_dists`（均值/协方差/模态概率） |
| **Reference Trajectory Planner (IPOPT)** | `smpc_agent.reference_regeneration` / 周期刷新中的 **`mpc_utils.RefTrajGenerator`**（内部 `Opti` + **`ipopt`**）生成可行参考 \(x_{\mathrm{ref}}, u_{\mathrm{ref}}\)，再裁成 SMPC 视界送入 `update_dict` |
| **SMPC Optimizer (Gurobi / SOCP)** | **`mpc_utils.SMPC_MMPreds`**（闭环反馈策略 + 可变/固定风险）或 **`SMPC_MMPreds_OL`**（开环近似路径）；CasADi `Opti("conic")` + **`gurobi`**（主实验路径） |
| **Policy parameters \(h, K, M\) + risk** | 在 `SMPC_MMPreds` / `SMPC_MMPreds_OBCA` 的 `_return_policy_class`、`_add_constraints_and_cost` 中定义；`fixed_risk` 与 `smpc_var_risk` / `smpc_fixed_risk` 对应图中 **Proposed vs Fixed-Risk** 分支 |
| **Open-Loop 方法** | `smpc_open_loop` → `SMPCAgent` 中 `ol_flag=True` → **`SMPC_MMPreds_OL`**（不建同一套 \(K,M\) 反馈树，与图中「弱化反馈/开环」一致） |
| **Control → Low-level (throttle/brake/steer)** | `run_step` 返回的控制在 **`utils/low_level_control.LowLevelControl`** 中映射到 CARLA `VehicleControl` |
| **Logging / Evaluation** | `RunIntersectionScenario.run_scenario` 写 `results_dict` → `scenario_result.pkl`；汇总用 **`compute_scenario_results.py`**（机动性、舒适性、安全 proxy、求解时间等） |
| **Receding horizon loop** | `run_scenario` 里 `for _ in range(self.max_iters):` + `sync_mode.tick`；每步 `policy.run_step(pred_dict)` |

**三策略与命令行名称：**

| 图中名称 | `run_all_scenarios.py --policies` |
|----------|-----------------------------------|
| Proposed（联合策略与风险） | `smpc_var_risk` |
| Fixed-Risk | `smpc_fixed_risk` |
| Open-Loop | `smpc_open_loop` |

**可选退路（非论文主求解器图）：** `--solver_backend ipopt_approx` → `ipopt_smpc_agent.py`，仅在没有 Gurobi 时使用；**主复现仍应对齐图中的 Gurobi 路径。**

## 2. 与 `SMPC.png` 的对应（单步 SMPC 管线）

| 图中模块 | 本仓库位置 |
|----------|------------|
| **Current Observation**（\(x_t\), \(o_t\), map） | `smpc_agent.run_step` 开头：自车位姿、速度；`pred_dict["tvs_positions"]`；地图在初始化 `GlobalRoutePlanner` / Frenet 时已嵌入 |
| **Multipath + post-processing** | `run_intersection_scenario._make_predictions`：栅格 `rasterizer.rasterize` → `pred_model.predict_instance` → `get_top_k_GMM`；输出进入 `pred_dict["tvs_mode_dists"]` |
| **Reference Trajectory Planner** | 同上：**`RefTrajGenerator`**（`mpc_utils.py`），由 `reference_regeneration` / 刷新逻辑驱动，得到 `feas_ref_states_new`、`feas_ref_inputs_new` |
| **SMPC Input Summary**（汇总 \(x_t\)、参考、GMM、界、视界） | `smpc_agent.run_step` 内组装的 **`update_dict`**：`x_ref, y_ref, …`、`mus/sigmas`、`tv_shapes`、`Rs_ev`、`acc_prev` 等 → `self.SMPC.update(...)` |
| **EV linearization / constraints / risk reformulation / SMPC solve**（对应论文式 (8)–(20) 的代码承载） | **`mpc_utils.SMPC_MMPreds`**（及 OL/OBCA 变体）中 `_get_LTV_EV_dynamics`、`_add_constraints_and_cost`、`solve`；**不在此文档逐行对齐公式号**，实现与 SMPC 上游同源 |
| **Control extraction（首步控制）** | `solve` 返回 `u_control`；闭环下与线性化点叠加后写入 `control_prev` / 低层控制 |
| **Low-level Interface** | `LowLevelControl` |
| **Actuation in CARLA + log** | `act.apply_control(control)`；`results_dict` 追加轨迹、可行性、`solve_times` |

## 3. 你关心的「一致性」结论（按流程图标准）

- **实验流程**：与 **`Experiment Flow.png`** 一致——JSON 场景 → CARLA 同步环 → 预测 → 参考（IPOPT 子问题）→ SMPC（Gurobi）→ 低层执行 → 日志/后处理；三方法由 `smpc_*` 切换。  
- **核心逻辑**：与 **`SMPC.png`** 一致——观测 → MultiPath GMM → 参考轨迹 → SMPC 输入汇总 → 锥规划求解 → 首步控制 → CARLA；闭环部分在 **`SMPC_MMPreds`** 中体现 \(h,K,M\) 与风险变量结构，开环在 **`SMPC_MMPreds_OL`**。  
- **与 SMPC 仓库**：实现载体为 **`core/scripts`** 中与上游同名的 `mpc_utils`、`smpc_agent`、`run_intersection_scenario` 等；另有一层 **CARLA 0.9.14 / 路径 / 蓝图** 适配，**不改变上述数据流与求解器角色分工**。
